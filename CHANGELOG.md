## [Unreleased]

### Added
- Support for 15 additional single-byte encodings (21 single-byte, 26 total):
  - Central & Baltic Europe: `WINDOWS-1250`, `ISO-8859-2`, `WINDOWS-1257`
  - Greek & Turkish: `WINDOWS-1253`, `ISO-8859-7`, `WINDOWS-1254`
  - Hebrew, Arabic & Thai: `WINDOWS-1255`, `WINDOWS-1256`, `ISO-8859-6`, `WINDOWS-874`
  - DOS code pages: `IBM437`, `IBM850`, `IBM852`
  - Mac encodings: `MACINTOSH`, `X-MAC-CYRILLIC`
- Optional `Fathom::Match#language : String?` field reporting the ISO 639-1 language code for single-language probers (`"ru"`, `"uk"`, `"be"`, `"pl"`, `"cs"`, `"hu"`, `"lt"`, `"lv"`, `"el"`, `"tr"`, `"he"`, `"ar"`, `"th"`, or `nil` for shared encodings).
- WHATWG encoding aliases and `Fathom::Encoding.iconv_name` mappings (`IBM437` → `CP437`, `IBM850` → `CP850`, `IBM852` → `CP852`, `IBM866` → `CP866`, `MACINTOSH`, `X-MAC-CYRILLIC` → `MACCYRILLIC`).
- `language` field in `tools/fathom.cr` human-readable and `--json` outputs, plus single-byte-only and shared-encodings ICU comparison summaries in `--corpus`.
- `Fathom::Chardetng`: a Crystal port of the single-byte and UTF-8 parts of [chardetng](https://github.com/hsivonen/chardetng) 1.0.0 (MIT/Apache-2.0; tables CC0), verified to give upstream's guesses on both corpora and 12,000 fuzzed inputs. Tables are generated by `tools/gen_chardetng_data.cr`.
- `Fathom::Prober#each_match` (defaults to `#probe`), so a prober can offer several ranked candidates to `Detector#detect_all`.

### Changed
- Single-byte detection now uses the chardetng port (`Fathom::Detector::DEFAULT_PROBERS`) instead of `Fathom::SingleByte::PROBERS`, which now only supply `Match#language`. Encodings chardetng lacks (`IBM437`, `IBM850`, `IBM852`, `MACINTOSH`, `X-MAC-CYRILLIC`, `KOI8-R`) use byte-class tables derived from chardetng's by character, start `100` points behind, and yield to `WINDOWS-1252`/`WINDOWS-1250`/`ISO-8859-2` whenever those read the input plausibly.
- Confidence for single-byte matches now reflects the score margin over the runner-up (`0.6` for a tie or punctuation-only input, up to `0.99`); `0.25` only when no encoding reads the input plausibly.
- Re-baselined `spec/accuracy_spec.cr`. On a held-out set built from the uchardet and chardetng test suites, accuracy rose from `286/359` to `333/359` (full files `125/159` → `153/159`); on `corpus/`, full files went from `200/202` to `201/202` while short slices dropped (`578/599` → `557/599` overall). Gate floors that fell: `WINDOWS-1250` precision `0.87` → `0.64`, `KOI8-R` and `WINDOWS-1254` precision `1.00` → `0.75`, `KOI8-U` recall `1.00` → `0.66`, `WINDOWS-1257` recall `0.83` → `0.66`, `IBM850` recall `0.88` → `0.77`, `IBM852` precision `1.00` → `0.90`, `MACINTOSH` recall `1.00` → `0.80`, `WINDOWS-1252` recall `1.00` → `0.94`.
- Switched single-byte training in `tools/train_models.cr` to row-conditional Markov bigram log-likelihood ratios (`ALPHA = 1.0`, eliminating per-encoding Latin handicaps and PMI workarounds) and derived the language list directly from `ALPHABETS`.
- Simplified `Fathom::SingleByte::Table#probe` to a unified bigram accumulator with soft all-caps discounting (`ALL_CAPS_FACTOR = 0.70`), symbol-only discounting (`SYMBOL_ONLY_FACTOR = 0.85`), mixed-script boundary detection, unexplained non-ASCII `CharKind::Other` accounting, and named penalty constants (`JUNK_PENALTY = 180`, `CASE_DROP_PENALTY = 80`).
- Compacted `src/fathom/tables.cr` from ~4,400 lines to ~2,370 lines using `.to_slice` byte-literal loaders (`SingleByte.load_bigrams` / `SingleByte.load_byte_map`), explicitly marked undefined `WINDOWS-874` bytes (`0xDB..0xDE`, `0xFC..0xFF`) as junk regardless of host `iconv`, and removed dead `CYRILLIC_MODELS`.
- Expanded `corpus/` and `spec/fixtures/corpus/` to 19 languages (`202` corpus files, `816` evaluated slices, `791/816` (`96.94%`) overall / `463/488` (`94.88%`) single-byte / `585/600` (`97.5%`) vs ICU `556/600` (`92.67%`) on shared encodings) and updated `spec/accuracy_spec.cr` thresholds to cover all 26 encodings.

### Fixed
- All-uppercase Western and Central European inputs (`GRÜSSE AUS MÜNCHEN` in `WINDOWS-1252`, `ZAŻÓŁĆ GĘŚLĄ JAŹŃ` in `WINDOWS-1250`) no longer collapse to `MACINTOSH` or `nil`.
- Mixed-script Latin pangrams with multi-diacritic words (Latvian in `WINDOWS-1257`) are no longer misclassified as Cyrillic `WINDOWS-1251`.
- Early `return` inside `tools/fathom.cr --all --json` that suppressed JSON output.
- Missing documentation for synthetic `IBM437/dos_1.txt` in `corpus/SOURCES.md`.

## [0.3.0] - 2026-11-22

### Added
- `Fathom::SingleByte::LanguageModel`, plus the `ORDER_SIZE` and `SCORE_SCALE` constants.
- `Fathom::UTF.incomplete_tail_size`.
- `ameba` linting (development dependency, `.ameba.yml`, CI step).

### Changed
- **Breaking:** `Fathom::SingleByte::Table.new` now takes `(encoding, model : LanguageModel, requires_high_letters, byte_map, handicap = 0)`.
- Single-byte confidence values are on a new scale (`0.25..0.99`); re-check any tuned `min_confidence`.
- Replaced unigram single-byte scoring with quantized `64x64` language-level bigram models (`Fathom::SingleByte::LanguageModel` and `Table`) trained via `tools/train_models.cr` on disjoint Wikipedia articles (`ru`, `uk`, `be`, and balanced `western`) and projected into `src/fathom/tables.cr` by `tools/gen_tables.cr`.
- `Fathom.detect_all` and `Fathom::Detector#detect_all` now deduplicate candidates by encoding, keeping the highest confidence per encoding.
- Corpus accuracy improved from `373/374` (`99.73%`) to `374/374` (`100.0%`) on `64B..full` (`16B..full` stays at `529/534`: the `KOI8-U` handicap that fixes short Russian `KOI8-R` words costs two 16–32-byte Ukrainian `KOI8-U` prefixes); raised `KOI8-R` precision and `KOI8-U` recall CI gate floors in `spec/accuracy_spec.cr` to `1.0`.

### Fixed
- Cyrillic words embedded in ASCII text (log lines, CSV with English headers) are no longer detected as `WINDOWS-1252`: the Western prober rejects input whose non-ASCII bytes mostly sit in runs of three or more.
- Short `IBM866` words (`хорошо`, `пароль`) are no longer detected as `WINDOWS-1251`: a non-ASCII letter now counts as isolated unless it touches another non-ASCII letter, so symbols such as `®` cannot act as word separators.
- Short `KOI8-R` text without Ukrainian-only letters (`да`, `Цена: 100 руб.`) is no longer labelled `KOI8-U`: the `KOI8-U` prober carries a small fixed handicap (`Table#handicap`) that fades as the input grows.
- `WINDOWS-1252` input whose only non-ASCII bytes are symbols (`100 €`, `§ 3`) is detected again instead of returning `nil`.
- UTF-8 input whose first multi-byte character is cut by the sample boundary is no longer rejected.
- `Fathom.decode` no longer raises on input that detection accepts with an incomplete final character (cut UTF-8 sequence, odd trailing UTF-16 byte, lone high surrogate); the partial character is dropped.
- Buffers that are more than 25% NUL bytes (all-NUL data, BOM-less UTF-32) are treated as binary instead of `UTF-8`.
- `OverflowError` in tolerant UTF-8 probing with very large custom `sample_size` values.

## [0.2.0] - 2026-11-22

### Added
- `Fathom.decode` and `Fathom::Detector#decode` (`Bytes` and `IO`) to detect encoding, strip any leading BOM, and decode via `String.new` with pass-through `invalid` handling.
- `Fathom::Encoding` (`SUPPORTED`, `ISO_WINDOWS_ALIASES`, `canonical_name`, `iconv_name`) and `Fathom::Match#iconv_name` aligned with WHATWG Encoding Standard labels (`ascii` maps to `WINDOWS-1252`) and the ISO/Windows `0x80..0x9F` alias rule.
- Tolerant UTF-8 detection (`Fathom::UTF.probe_tolerant_utf8`) returning `UTF-8` with lowered confidence based on the ratio of valid multi-byte UTF-8 sequences to invalid high bytes.
- Accuracy corpus under `corpus/` built from Wikipedia text by `tools/gen_corpus.cr`, and a CI accuracy regression gate (`spec/accuracy_spec.cr` over `spec/fixtures/corpus/`).
- Cross-platform `iconv` decode verification spec (`spec/iconv_spec.cr`) and CI matrix across Linux glibc, Alpine musl, macOS, and Windows.
- Lightweight CLI tool at `tools/fathom.cr` for file/stdin inspection, decoding, and corpus accuracy benchmarking (with optional `icu` / `uchardet` comparison).

### Fixed
- Latin text with isolated accented letters (e.g. Italian word-final `è`) is no longer detected as `WINDOWS-1251`: Cyrillic probers now reject input where most non-ASCII letters stand alone between ASCII bytes. Corpus accuracy 364/374 → 373/374.

## [0.1.0] - 2026-11-22

### Added
- Pure-Crystal character encoding detection with zero runtime dependencies and zero-allocation hot paths.
- Byte Order Mark (BOM) detection for `UTF-8`, `UTF-16LE`, `UTF-16BE`, `UTF-32LE`, and `UTF-32BE`.
- UTF-8 and ASCII detection, including truncated trailing multi-byte UTF-8 sequences and NUL-terminated strings.
- BOM-less `UTF-16LE` and `UTF-16BE` detection via null-byte parity and code-unit validation.
- Single-byte encoding probers backed by precomputed `StaticArray` lookup tables (`WINDOWS-1251`, `KOI8-R`, `KOI8-U`, `ISO-8859-5`, `IBM866`, and `WINDOWS-1252`).
- Public API: `Fathom.detect`, `Fathom.match`, `Fathom.detect_all`, `Fathom::Match`, `Fathom::Detector` (supporting both `Bytes` and `IO` streaming), and pluggable `Fathom::Prober` interface.
